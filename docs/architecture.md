# 架构设计

## 核心流程（输入 → 处理 → 判断 → 输出 → 验证/反馈）

```
                ┌─────────────────────────────────────────┐
                │  触发：交易日 20:30（WorkBuddy 定时任务）  │
                └──────────────────┬──────────────────────┘
                                   ▼
【输入】  config/stocks.json（自选股清单）
          config/settings.json（复盘参数）
          腾讯自选股连接器（行情、板块、资金流、新闻公告）
                                   ▼
【处理】  AI 汇总原始数据 → 按契约组装成当日 JSON
                                   ▼
【判断】  数据完整性检查：字段缺不缺？交易日对不对？
          ├─ 数据不全 → 记录缺失原因，仍出报告（标注"数据不全"）
          └─ 非交易日 → 不跑，只更新交接卡说明
                                   ▼
【输出】  ① data/daily/YYYY-MM-DD.json（数据存档）
          ② data/index.json 追加日期索引
          ③ outputs/YYYY-MM-DD.html（单文件报告，可发朋友）
          ④ web/ 页面刷新后自动可见（它只读 data/）
                                   ▼
【验证】  tests/validate_data.py 校验当日 JSON 结构
          报告文件确实生成、能打开
          ├─ 通过 → 更新交接卡"今日复盘记录"
          └─ 失败 → 错误详情写入 archive/debug_logs/，交接卡标注待处理
```

## 模块拆分与职责

| 模块 | 位置 | 职责 | 不做什么 |
|---|---|---|---|
| 数据采集 | AI + 连接器（无代码） | 拉大盘与自选股原始数据 | 不做展示、不做存储决策 |
| 数据契约 | `docs/data_contract.md` | 定义 JSON 字段，数据与展示的"合同" | — |
| 复盘判断 | `config/settings.json` + AI | 阈值判断异动、生成点评文字 | 不碰页面 |
| 网页展示 | `web/` | 读 JSON 渲染当日视图 + 历史列表 | 不拉数据、不写文件 |
| 报告渲染 | `templates/report.html` + AI | 生成单文件 HTML | 不做交互 |
| 校验 | `tests/validate_data.py` | 对照契约校验 JSON | 不改数据 |
| 调度 | WorkBuddy 自动化任务 | 交易日 20:30 触发复盘 | 不含业务逻辑 |

模块间数据契约：全部围绕 `data/daily/*.json` 这一份文件——上游（采集）按契约写，下游（网页、报告）按契约读。任何一方要改字段，先改 `docs/data_contract.md` 并经用户确认。

## 设计取舍说明

- **为什么无后端**：数据一天只更新一次，静态文件完全够；少一层少一片故障区
- **为什么网页不直接调行情接口**：避免接口变动拖垮页面；数据落地成 JSON 后，网页永远能打开
- **为什么双产物共用一份 JSON**：一份数据两处渲染，不存在两边对不上的问题
